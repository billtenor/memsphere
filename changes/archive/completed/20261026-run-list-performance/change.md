# 运行列表加载性能优化

## 需求

### 整体目标

进入 View“运行 → 运行中”时，及时看到运行列表，不再为展示基本信息等待所有自由探索 Run 的完整上下文读取和恢复。继续使用现有运行模块、导航和详情界面。

### 来源与现状

- Human 请求启动敏捷迭代处理列表加载缓慢，并确认：“运行中的列表，理论上只需要查 run 的 store 就够了吧？”
- 先前分析 Run：`run-20261026-065232z-f1d74c90`，已完成；其“最终交付结果简述”记录测量、代码归因和原始证据位置。
- 基线代码：`f6a7df3cbe0e375b1987a780238f22e60399f254`。
- 本机真实 Project 的同一列表接口连续三次约 1.18、1.24、1.12 秒；页面首次进入发出两次相同摘要请求，后一个耗时约 2.42 秒。自由探索仅 3 个 Run，摘要路径却调用记录 get 共 778 次；服务及模型 Store 装配约 0.59 秒，摘要计算约 0.56 秒。这些是现有数据下的样本，不是跨机器承诺。
- 当前摘要路径读取 Artifact、Step、External、Review，执行恢复，再计算完整快照指纹，最后才筛选状态；首页卡片和列表重复请求同一摘要。旧流程已有摘要缓存，重复读取约 9 毫秒，不应作为本轮主要重构对象。
- 无重复 active 需求。关联需求：`20261024-context-control-exploration` 已登记列表性能后续项；本轮落实该后续项。

### 当前迭代范围

1. **列表只读取运行摘要。** 自由探索摘要的业务记录读取仅来自 Run Store，不读取其产物、步骤、外部资料和评审，不生成上下文快照，也不执行生产恢复。按请求的状态和归档范围返回正确条目，沿用创建时间倒序及现有来源冲突检查。
2. **明确列表信息边界。** 保留名称、运行标识、状态、现有操作入口等 Run 本身可提供的信息。自由探索列表不再为产物数量、完整上下文指纹或由 Step 推导的最近产出时间阻塞查询；拿不到的派生信息不以 0 或旧值冒充真实结果。旧流程现有摘要与评审进度展示保持可用。
3. **消除重复加载成本。** 同一 Project 的首页卡片与运行列表同时需要相同摘要时，共享在途请求或避免不必要请求；失败可以重试，不能长时间缓存旧结果。View 复用已初始化的模型及 Store 资源，并在模型或存储配置发生有效变化后刷新或明确报错，不能继续访问过期绑定。
4. **列表与详情分离。** 打开具体 Run 后再读取其产物图、评审和详情，保留相应恢复能力。列表查询不以修复无关产物为前提；某个 Run 的子记录故障不阻塞其他 Run 的基本列表。用户刷新或业务操作成功后，所选 Run 的详情仍能更新，不依赖从列表移除的完整快照指纹。
5. **覆盖共用摘要入口。** 同一摘要接口服务的已完成、已废弃、已归档列表及首页保持筛选、跳转和操作一致；不只对“运行中”作特殊绕过。跨 Project 不共享错误的数据或请求。

### 后续范围与不做事项

- 本轮不迁移旧流程存储，不变更五个领域模型或新增 Run 派生统计字段，不改变 report、outputs、正式 Review 或生命周期规则。
- 不引入远端数据库、外部缓存、额外后台同步任务或持久化摘要索引。
- 不重做产物图布局、修改主题或增加新模块；前端只调整本轮必要的信息展示和加载行为。
- 不将单次验收日志、截图、诊断脚本等原始证据提交到 Git；证据由 Run 留存。禁止强行提交被 gitignore 忽略的文件。

## 验收结果

受影响 27 项回归、typecheck、build、项目 Memory 校验通过；完整 `npm test -- --test-concurrency=4` 为 163 文件零失败、1360 项通过、2 项 Windows 专属平台跳过，耗时 298.78 秒。研发、架构、测试三位 Agent 已独立通过实现验收（各复跑直接相关20项），Runner 已接纳；Human 产品负责人与产品 Agent 均已通过交付评审，Runner 已接纳。独立真实 View 服务同机同数据测量：预热摘要 API 中位数 992.67 → 16.75 毫秒（降低 98.31%），新页面列表可操作中位数 3160.30 → 566.50 毫秒，11 条列表不变，相同摘要请求从两份降为一份；服务冷启动页面样本 3587 → 1632.30 毫秒。实际预热业务读取为一次 Run list 和三次 Run get，不读四类子记录。流程自身记录增长不作为用户数据删除或数据规模缩减；完整原始性能样本随 Run 初始验证报告持久化，不纳入 Git。

## 后续性能边界

- 自由探索详情只读取目标 Run 的业务正文，但 ValueStore 仍枚举整个 Store 的文件名，再按 run_id 筛选；Store 打开还有目录协议检查。此处未随本轮列表优化改动。
- 全局搜索仍使用四个状态 URL，各自读取所有 Run 摘要后筛选；同 URL 在途共享无法合并不同状态请求。架构评审已作为非阻塞后续项登记。
- 上述边界不影响本轮列表首载验收；没有承诺详情完全避免目录枚举，也没有将旧流程迁移或新持久化索引加入交付。
