# 自由探索体验优化：当前迭代需求契约

状态：待产品负责人评审。迭代基线：73c60253b0949e10cd166538fb37c20b8095faeb。

## 整体目标

减少自由探索中重复参数、多余操作和长正文回显带来的负担，改善 Human 浏览依赖图的体验。Continue 保留 Memsphere 全局入口和共性概念，本轮仅支持自由探索 Run。

需求依据：自由探索 Run `run-38cead01-82f2-4079-9c91-8e6c8a35aa20` 中的最新需求产物 `artifact-db8d7e1c-50bf-4e87-ba6d-fc74dd747695`，以及其关联的问题、方案和用户确认。原体验中借用的业务故障调查不是本轮范围。

## 当前迭代范围

| 编号 | 功能与要求 |
| --- | --- |
| F1 | Continue 自动承接自由探索前文。普通场景显式传自动生成的前文 ID；我们自己发起、需要操作自由探索的 ACP 在启动时注入默认 ID，不依赖单次 Shell export。只继承公共参数，具体材料、内容、依赖、意见来源和修订对象仍由 Agent 指定 |
| F2 | continue <ID> --help 显示自由探索当前可执行操作、已承接及仍需填写的参数；普通帮助同步准确说明自由探索的实际用法 |
| F3 | 取消普通自由探索的 artifact create 和读取 --for。Agent 按需读取、本地生产，阶段成果完整后直接 report；系统关联 Step。轻量 Review、不可变修订和回到旧成果重做继续可用 |
| F4 | 每份前文独立记录两次成功 report 之间的读取，并将上一份 report 的产物作为候选。成功 report 存在未覆盖候选时，必须返回可识别的非阻断提醒；无候选不制造提醒，失败 report 不推进窗口。不自动加边、不强制确认或补读，不阻断正常读取和提交 |
| F5 | external add 成功回执仅提供 runId、externalId，text 与 JSON 信息一致，不重复输出来源和正文 |
| F6 | 自由探索 Artifact、External 读取正文过长时截断，以 ... 结尾，提示保存完整正文到文件的具体命令。--output json 仍输出单一合法、可解析的 JSON，截断正文与截断说明、导出提示可明确区分；文件导出保持完整且不混入提示 |
| F7 | 自由探索产物图展示 External 节点及已经保存的实际依赖关系，结合当前和历史版本视图准确呈现 |

| F9 | 边悬停时进入与节点一致的高亮状态，同时高亮其直接连接的所有节点 |

### 前文的生成与提示

普通调用在成功进入自由探索的明确入口后取得前文 ID；在同一前文内部推进、report 和轻量 Review 沿用该 ID。不同 Runner 可以在同一个 Run 内拥有独立前文，不能直接用 Run ID 替代。

入口 JSON 回执包含 contextId；文本显示前文 ID 和 continue <ID> --help 的短提示。受控 ACP 的启动环境可提供同一 ID 作为默认值，显式 ID 优先。普通独立命令不自动创建或覆盖前文。

通用前文只表达命令组及公共上下文，不固定带 Run 专用字段；读取辅助信息属于自由探索的业务扩展。具体字段、存储和失败恢复设计在技术方案阶段讨论。

## 明确不包含的范围

- 旧 Procedure Run、Schema 写作、正式 Review 和 Memory ChangeSet 的命令、状态机及既有使用方式暂不改造，不为其接入 Continue。
- 旧正式 Review ACP 会话不因本轮建设而改用新的继续协议；新默认 ID 注入只适用于本轮接入的自由探索操作。
- 不新增图编排语法、YAML syntax 关键字、图上编辑依赖、自动重跑代码或业务故障修复。
- 不新增需要 Agent 手动创建、命名、设置及关闭的重型 Session。
- 不将独立的生产目标改名入口或反向索引作为额外功能要求。实现中必要的定位设计须在技术方案中明确，不能扩大用户动线。

未来可将公共 Continue 能力接到其他命令组，但不属于本轮交付。

## 验收标准

| 编号 | 应观察到的结果 |
| --- | --- |
| AC1 | 从自由探索入口获得可用前文 ID，无需 artifact create 或 session create；继续执行时能省略公共参数并保持同 ID |
| AC2 | 普通调用可跨独立 Shell 显式延续；受控 ACP 启动注入后可省略 ID；显式 ID 优先，不依赖之前执行 export |
| AC3 | 同一 Run 内不同前文的公共上下文、上一份产物和读取窗口互不混入 |
| AC4 | continue help 与实际可执行操作一致；不能将旧流程 Run 或 ChangeSet 误报为本轮支持的继续对象 |
| AC5 | 不预建空目标即可 report → 轻量 Review → 本地修改 → report 修订；历史内容保留，依赖可继承或显式替换 |
| AC6 | 已掌握材料可直接引用，不要求补读或填写 --for；辅助记录故障不影响正文获取，不把已成功提交误报为失败 |
| AC7 | 成功 report 时，本前文窗口存在未覆盖的已读材料或上一份 report 候选，必须返回可识别的非阻断提醒；无候选不制造提醒，失败 report 不推进窗口。候选不自动成为依赖，不伪造读取事实，不强制补齐 |
| AC8 | external add 两种输出只包含 runId、externalId；长正文不扩大成功回执，完整资料仍能读取 |
| AC9 | 当正文超过已确定阈值时，Artifact 与 External 都截断并显示 ... 及完整文件导出命令。--output json 仍返回单一合法、可解析的 JSON，能够区分截断正文与说明、导出提示，不在 JSON 后追加纯文本；--out 导出文件与存储的完整正文一致，不截断、不混入提示。具体回执字段在技术方案中确定 |
| AC10 | 图中可看到 External 及真实依赖边；切换历史版本时 External 关联和 Artifact 图保持一致 |
| AC11 | 大图可连续双向拖拽平移；松开或取消后停止；拖拽不会被误认为点击节点，现有详情和历史切换仍可用 |
| AC12 | 悬停边会同时高亮边及全部直接端点；移出后结束此次高亮，同时不错误清除其他合法选中或悬停状态 |
| AC13 | 本轮共享 CLI/View 改动不破坏旧流程、Schema、正式 Review、ChangeSet 及已有已提交成果读取 |
| AC14 | 帮助、文档、Skill 与 System Memory 一致，适用测试与真实交互验证有实际证据；有 Memory 差异时完成最终 ChangeSet 校验 |

截断阈值、External 无引用节点的展示方式、拖拽按键及命中细节等，须在技术方案阶段与 Human 讨论并固定，实施和验收以已确认方案为准。

## 向前兼容

结论：不需要向前兼容。

已检查本地及远端 origin 名称包含 stable 的 Git Tag，当前未发现此类稳定 checkpoint。本轮不承诺未发布自由探索空目标接口的原样兼容，也不要求为其建设通用迁移体系。

这不解除明确的范围和数据要求：旧流程 Run、Schema、正式 Review、ChangeSet 的现有行为不改造；已提交成果、依赖及历史应继续可读，不删除用户数据。现存自由探索空目标如何收敛，由技术方案检查真实数据后给出适度处理方式。

## 方案阶段的讨论安排

需求契约评审通过后，正式 Run 到达“实施与验证方案”步骤时，额外创建一个自由探索 Run 专门撰写技术方案。届时以其 Artifact 分别记录问题、选择和阶段结论，Human 全程参与讨论；收敛后将完整方案提交回本敏捷 Run 的正式技术评审。

该探索 Run 不替代正式 Run，也不绕过研发、架构、测试评审。现在不提前创建或开始技术方案。
