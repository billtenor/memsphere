# bug 理解摘要

## 实际行为

正式安装并启用的可信本地 View Package 请求公开 SDK 的 Router 时，在 Plugin apply() 之前被授权校验拒绝，实例不能 active。原报告中的实例页面同时返回 404，但这一现象与注入失败并存，不能仅据此断言它是 Router 注入失败的结果。需独立验证服务端是否为正式外部实例返回 Shell 页面。

## 期望行为与修复范围

支持可信本地 Package 新增独立业务 Module。通过 Manifest 中的显式能力声明获得 Router，路由以 `/projects/<projectId>/modules/<instanceId>` 为基路径。普通包不获得 App backend API，也不取得内置路由特权。支持自身页面的导航、Header、对象列表与正文组合，列表选择、关联跳转、直接打开、刷新及浏览器前进/后退保持一致。

明确以下边界：未安装、禁用或未获 Router 授权的实例页面不可访问；已获授权但浏览器加载失败或路由未知时，在 Shell 内说明错误并保留诊断。仅选择 Package 主题不启用独立业务路由。拒绝冲突或越界路由，并撤销失败实例的注册事务。既有 Memory/Run/Models 展示替换、builtin、development 和 App 绑定实例行为保持兼容。

本次处理通用 View Package 契约与入口，不实现 CRAA 爬虫业务，不硬编码包 id，不扩展任意后端 API 权限，不升级 Node 要求。

## 影响范围

受影响路径是正式本地 Package 的独立业务模块接入，而非所有既有页面展示替换。修改会涉及 Manifest 能力枚举、服务端实例授权与页面入口、运行时安全路径校验，以及中英文开发文档与自动化回归。能力授权应使用正常安装/组合配置和启动快照，不能通过注入白名单绕过或业务特例实现。

## 已知证据与验证边界

- Issue #87 提供最小注入示例、正式安装步骤及报错；其 Node 20 环境不在仓库支持范围内。
- 原代码 externalViewInstances 给普通外部实例的服务包含 slots/theme/presentation/ui；Router 原先仅向 App 绑定实例开放。
- validateServices 在 apply() 前检查 Host 计算的 allowedServices，拒绝未授权的 router。
- 原服务端请求分支识别 core/builtin/development 及 App 实例页面，遗漏普通外部实例命名空间。
- SDK 已将普通 Module Route 注册限定到实例基路径，并通过 Route Token 和事务组合 Slot。
- 现有文档的独立 Module 编程示例与正式外部实例授权未说明上述差异。

前一轮对话已经产生未提交代码、测试和双语文档草案，并在 Node 22.16.0/Linux 下完成构建、类型检查和相关回归。正式流程开始时间晚于这些工作，不能伪装成已按流程批准后实施。现有改动仅作为待评审草案保留；须在本 Run 中完成理解确认、根因和测试缺口分析、方案评审后，再核对或修订实现并形成正式验收证据。

## 验收口径

1. 经正式设置接口安装、校验、保存、启用、重启后的独立 Package 实例 active，并显示导航与页面。
2. 路由属于自身 Project / instance，冲突及越界明确拒绝且原子撤销。
3. 列表对象选择、关联跳转、直接打开、刷新、前进/后退一致。
4. 未安装、禁用、无能力声明、未知路由及加载失败行为明确。
5. 既有展示扩展、builtin 页面与 App 不回归，文档描述真实契约。
6. 报告明确 Linux/Node 22 实测范围及未执行的平台或业务集成，不将已有草案验证冒充正式验收完成。
