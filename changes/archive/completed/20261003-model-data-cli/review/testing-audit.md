# PR 85 测试规范与耗时检查

Human 在 CI 跟进中要求重新检查测试规范。已通过 CLI 完整读取 statements/memsphere-repository-testing-rules 与 development rules。本次没有改写规范或已批准的需求、方案、验收和交付报告。

## 规范要求与当前问题

- 测试必须保护明确的用户可观察契约，选择能覆盖风险的最低层级；非被测前置状态优先通过 Store、API 或 helper 构造。真实 CLI 协议、文件锁和浏览器交互仍需在真实边界验证，不能因为较慢就改成只测函数。
- 自动化测试不得依赖机器速度和未受控时序；必须等待目标状态并设置超时。先等待元素出现，再分别读取会被重绘替换的 DOM，没有遵守这项稳定性要求。
- 修改后先验证受影响文件，再跑完整回归；不得通过跳过测试、删除或弱化断言解决失败。本次没有更改 CI 超时、串行配置或平台跳过规则。

## 已定位的失败

1. macOS Project 根路径别名、Windows 临时目录短路径导致路径校验或测试注入目标不一致：修正可信 Project 根路径与 fixture 的实际路径处理，内部 symlink 和越界限制保留。
2. Windows 并发编辑测试在读取快照后仍持有文件句柄：改为关句柄后再暂停；失败清理等待 exit 并销毁管道，避免等待后代进程持有的 stdio close。下一轮 Windows 并发编辑已通过，完整套件正常跑完。
3. Ubuntu 模型信息测试在两次 DOM 查询之间遇到路由重绘：一次捕获完整状态，原字段顺序、字段值、选中状态等断言保留。
4. Windows 结构展示测试等待首次标题超时：该展示测试直接进入规范化地址，已有深链接覆盖保留；失败时附加 URL、API 响应、页面正文和 pageerror 诊断。修复效果须由新一轮 Windows CI 确认，不能仅凭本地成功下结论。

## 检查结论

规范已有明确要求，问题在部分测试的落实。源码重复加载是可立即移除的启动成本；文件句柄和 DOM 竞态须修正控制方式。串行全量、浏览器启动及多个协议组合的真实边界覆盖仍会产生耗时，后续分层优化应逐条证明受保护契约，不能直接删除较慢测试或用提高并发掩盖竞态。
