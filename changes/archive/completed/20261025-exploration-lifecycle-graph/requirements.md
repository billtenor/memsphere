# 自由探索结束归档与依赖图优化：需求契约

## 整体目标

自由探索在现有 Run 界面形成完整的结束和归档动线，并让包含跨层依赖的产物图更容易阅读。

来源：Human 本轮反馈，自由探索缺少可见的结束与归档操作；截图中直接依赖和跨层依赖的线条重叠，难以追踪。

## 当前迭代范围

| 编号 | 功能 | 期望行为 |
| --- | --- | --- |
| F1 | 结束自由探索 | 在现有 Run 页面顶部提供“结束运行”，确认后以当前成果结束。CLI 沿用 `run finish --run R` 和 `continue C finish`，省略产物列表时采用当前推导成果；仍支持显式指定交付产物。 |
| F2 | 终态归档与恢复 | 已完成或已废弃的自由探索 Run 可以归档，从普通运行列表隐藏；通过 Run 列表中的“已归档”入口可重新找到，原地址也可只读查看，并支持恢复归档。恢复仍为原来的终态，不重新进入运行中。 |
| F3 | 沿用归档命令 | `archive run R`、`archive list runs`、`archive restore run R` 同时支持自由探索和原有流程运行，各自沿用合适的持久化逻辑。 |
| F4 | 依赖图布局与视觉 | 参考 Human 已认可的 Dify 画布方向，改进卡片密度、信息层级、节点布局与连线；保留现有绿色主题、Badge 和公共组件。长边绕开中间节点，多条连线可区分，箭头准确表达依赖方向；不将跨层边统一绕至顶部造成长距离绕线和大片留白。 |
| F5 | 相关说明一致 | 模型、CLI 文档、Skill、System Memory 与实际行为同步。已要求纳入的 `docs/procedure-graph-syntax.md` 作为设计草案随代码交付，不据此实现新语法。 |

## 交互与行为边界

- 运行中：顶部提供结束运行、废弃；结束确认显示本次交付成果的数量和名称，为空时明确显示“无交付成果”；废弃沿用 Human 决定的语义。
- 终态：可以归档。运行中直接归档明确失败，不隐式结束或废弃。
- 归档后：普通状态列表隐藏，数据及历史记录保留；Run 模块提供“已归档”列表入口，至少可找回本轮支持的自由探索记录。由此进入或直接打开原地址都可查看内容与评审，并恢复归档。恢复后终态不变。
- 空自由探索也允许结束；当前成果为空时不偷偷选择所有产物。
- 正常结束后禁止继续提交或修改产物、依赖与评审；前文不再提供生产状态流转。
- 结束、归档和恢复的同义重复操作不重复生产产物、不损坏记录。
- 归档不得删除或重写 Artifact、External、Step、Review，不修改既有内容引用，不要求 Store 采用本地目录搬迁。
- 调整的是展示布局与路径，不更改真实依赖关系。原有悬停高亮边及直接端点、手抓平移、历史切换、浮窗内容和翻页继续有效。
- 不自动结束或归档用户已有的自由探索 Run；验收使用专门测试数据。

## 后续范围

本轮不增加图编辑器、缩放、任意手工拖动节点、自动图简化或新图语法执行器；不建设新的 Run 模块；不把旧流程持久化迁移为新模型；不扩大 Continue 的适用命令组。

## 交付物

1. 现有 Run 页面的结束、归档和恢复入口，以及配套 CLI/API。
2. 对跨层和多重依赖可读的图布局与连线。
3. 同步的模型、命令说明和 Memory；既有数据的受限模型升级路径。
4. 覆盖正常和边界行为的自动化测试、真实 View 交互验收记录、实施与交付说明。
5. 既有待纳入的流程记忆图语法设计草案，保持设计草案性质。

## 验收标准

| 编号 | 可观察结果 |
| --- | --- |
| AC1 | 有成果的运行从页面和 CLI 都能结束，默认交付集合等于结束前的当前推导成果；显式交付根仍生效。 |
| AC2 | 空运行能结束；已有非空成果 A 时，结束 API 省略 `artifactIds` 表示采用当前推导成果，显式传 `artifactIds: []` 表示确认空交付集合。验收先产生 A，再用显式空数组结束，断言最终交付根为空；重复相同结束请求无额外写入，终态无法继续生产。CLI 无需新增空集合参数：先通过既有 `outputs update --remove A` 明确移除全部当前成果，再 `run finish` 即确认空集合。 |
| AC3 | 运行中归档失败且状态、证据不变；done 和 abandoned 可归档。 |
| AC4 | 归档后不出现在普通状态列表；离开详情后仍可从 Run 模块“已归档”入口找回记录，进入只读详情并恢复。原地址跨刷新/轮询仍可查看内容与评审；不要求用户提前保存 URL 或使用 CLI 才能找回。 |
| AC5 | 页面和 CLI 恢复归档后重新出现在相应终态列表，仍禁止生产；重复归档/恢复安全。 |
| AC6 | 归档和恢复前后产物、资料、Step、Review、交付根及依赖保持一致；不删除模型 Store 中的证据，不破坏既有引用；具体归档存储方案留到技术评审确认。 |
| AC7 | 用本轮截图对应的实际复杂依赖图对齐原型：卡片紧凑、信息层级清晰，长边不穿过中间节点且不集中长距离绕顶，多条边可区分；保持现有绿色主题与 Badge，箭头方向和悬停端点准确。具体原型经 Human 确认后再进入实现。 |
| AC8 | 历史切图、浮窗翻页、窄屏阅读、横纵手抓平移保持正确，真实页面无新增错误。 |
| AC9 | 旧流程的运行、废弃、归档、恢复保持原语义；已存在的五模型数据不丢失。只需增加可选字段时不重写每份 Run。 |
| AC10 | `npm run typecheck`、`npm run build`、`npm test`、`memsphere validate` 通过；存在 Memory 差异时变更级校验有效，并实际使用 playwright-cli 验收受影响交互。 |
| AC11 | 逐项核对 `reserved-models/context-control/run.json`、`docs/context-control-exploration-cli.md`、`src/skills/memsphere/SKILL.md`、`reserved-memory/system-memory/concepts/memsphere-run.yaml` 及 `.memsphere/memory/concepts/memsphere-run.yaml` 的描述与实现一致：Concept 只解释 Run 的含义、职责和关系，操作规则由规范、Skill 与 CLI 文档承载；源/副本保持同步；核对 `docs/procedure-graph-syntax.md` 仍为设计草案，本轮无对应 parser、schema 或执行器的新语法接入。验收材料列出核对位置与结果，不能只引用 build/test 成功。 |

## 向前兼容

结论：不需要向前兼容。

当前本地仓库未发现名称含 stable 的 Tag，按仓库规范没有需承诺兼容的 stable checkpoint。该结论不授权破坏当前使用中的数据：AC9 仍要求保留现有流程行为、五模型记录和终态选择，并提供已知旧模型的显式升级。

## 采用的规范

- memsphere-repository-requirement-rules：需求范围与向前兼容结论。
- memsphere-repository-development-rules：避免过度设计；模型、System Memory、安装副本与 Skill 同步。
- memsphere-repository-testing-rules：受影响测试、全量回归、真实浏览器验收和 Memory 变更校验。
- memsphere-repository-delivery-rules：后续验收与交付归档记录。
- memsphere-run：Run 的含义、两种模式、执行角色和状态关系。
