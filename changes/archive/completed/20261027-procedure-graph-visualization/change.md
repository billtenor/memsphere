# graph 记忆定义与运行可视化

## 需求

Human 请求：启动敏捷需求迭代，改善 `mode: graph` 的记忆展示，以及这类记忆运行后的展示。

整体目标：用户在运行前能理解流程，在运行中能判断进度与等待原因，在运行后能追溯具体执行、评审和产物。2026-10-28 Human 对迭代讨论后的原型明确投通过；以下范围和交互方向作为数据接入的需求基线。样式细节在接入真实数据后继续微调。

### 现状与依据

- `modules/org.memsphere.memory/adapter/view/index.ts` 的 `renderProcedure` 对 graph 展示展开的 Action 卡片，dependencies、collect、artifact 主要以 JSON 呈现，没有定义关系图。
- `modules/org.memsphere.run/adapter/view/context-control.ts` 展示 Step 列表和 JSON 定义，已有产物依赖图、产物历史及正式评审入口，缺少基于定义的执行总览。
- `docs/procedure-graph-syntax.md` 已区分 Action 定义、Step 实例和 Artifact；定义图允许循环，具体产物依赖图为 DAG。不同 dependencies 项表示独立触发，同一 from 数组表示共同等待；collect 固定实际产物引用，不生产额外聚合 Artifact。
- `test/procedure-graph-view.test.ts` 与 `test/procedure-graph-view-browser.test.ts` 已保护读取不推进运行及指定 Step 的评审入口，应保留这些契约。
- active 需求中未发现重复需求；强关联已完成需求为 `20261026-procedure-graph` 与 `20261025-exploration-lifecycle-graph`，沿用已有运行语义与图展示基础。

### 当前迭代范围

1. **记忆定义图**：在既有 Memory 详情内展示 START、普通 Action、collect、依赖方向、条件和循环回边。共同等待和独立触发在视觉上可区分，collect 的收集关系与执行依赖有明确区分。
2. **节点详情**：选择 Action 后阅读完整工作描述、执行角色、规则、产物模型和 MIME 类型、评审要求；collect 展示收集来源。保留可定位原始定义的入口，以及现有变更比较、评论定位能力。
3. **运行总览**：在既有 Run 详情内基于该 Run 冻结的 Procedure 定义显示执行状态，覆盖尚未产生 Step 的 Action；展示每个 Action 已产生的实例数及各状态数量，能找到可执行实例、正在执行实例、待评审实例及等待中的依赖。
4. **执行追溯**：Action 下可选择具体 Step，读取固定输入、执行状态、产物与评审。循环的多次 Step 按实例分别查看；同一 Step 的多次提交按修订历史查看。继续复用已有产物依赖图和正式评审入口。
5. **阅读体验**：沿用现有主题与公共组件；画布支持平移、适配全图和缩放，悬停反馈清晰，长名称可读；刷新不打断仍在查看的内容和阅读位置。关闭详情后清除高亮，保留画布位置与缩放。窄屏和键盘用户可通过等价列表进入节点详情。

### 后续范围与不做事项

图形编辑、拖线修改 YAML、从画布触发运行或代执行 Step、修改调度规则、新语法、跨 Run 对比和时间轴回放留到后续迭代。当前迭代围绕读取与追溯，不新增执行命令；已有正式评审交互继续沿用。
