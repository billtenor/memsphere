# 需求

## 整体目标
以用户可观察契约和实际故障风险为依据，减少测试数量、重复跨平台执行和重复基础开销；同时降低 PR 反馈时间与总 runner 消耗。不是继续增加并行作业来满足时间门禁。

用户明确要求：基于最新 master，在当前 worktree 开新分支，启动敏捷需求迭代；目标是按照前述审计思路删减测试。用户额外参与架构师评审，其余角色绑定对应 Agent。

## 当前迭代范围
1. 审计现有自动化测试，按保护契约、实际运行边界、跨平台必要性、重复覆盖与维护成本形成处置清单：保留、下沉、合并/去重、移出 PR、删除。
2. 实际删除或合并一批不能独立保护有效契约、重复覆盖、过度组合的测试；API/纯逻辑断言如可由低层可靠覆盖则下沉。删除和替代必须给出逐项理由与剩余保护位置，不能只重命名、改分片或跳过失败测试。
3. PR 默认在一个主要平台运行完整的保留核心回归和精简浏览器集成；三平台保留对文件系统、锁、路径、进程、Shell、安装包等真实差异的必要检查。
4. 对仍有价值但不需要逐 PR 全量重复的跨平台/布局组合检查提供明确可执行的定时或发布前入口；所有保留测试都有执行归属，无无意遗漏。具体矩阵和删除清单由架构评审确认。
5. 保留发布与升级回滚、用户数据保护、权限边界、Run 状态/并发等高风险契约。精简测试准备和重复构建时保持隔离性。
6. 更新测试运行脚本、CI 配置、调度与覆盖自检，以及必要的开发说明。若现有 Memory 的长期规则确需调整，再通过源文件及安装副本同步和 ChangeSet 校验完成。

## 后续范围与不做事项
不改变产品功能、Memory DSL、数据格式、权限模型；不开展一般运行时代码重构。不承诺消灭所有慢测试或偶发环境失败；不建设复杂自动变更影响分析平台。不以测试通过数量作为质量目标，不删除无替代的高风险边界保护。本轮先保留 PR 五分钟反馈目标及原门禁阈值；排队性能与正确性如何长期分离，列为后续议题，除非架构评审确认纳入并更新契约。

## 验收标准
- 对实际删减、合并、下沉、降频的每组测试可追溯其主要契约、理由、替代保护或明确接受的覆盖减少；不得借此隐藏确定性失败。
- 确定性收益门槛：PR 默认测试文件执行总次数相对基线444次（148×3）至少减少40%，即不超过266次；测试/打包的完整构建次数从18次降到不超过8次。实际删除至少4条无独立有效契约的测试，并减少至少一组过度浏览器组合；删除清单及覆盖代价先由架构评审确认。不得只通过调度缩短墙钟时间。报告文件/用例或组合数、平台执行次数、矩阵作业和构建次数的前后值。总作业耗时按GitHub各测试/打包job的completedAt-startedAt相加计算（包含安装/构建，不包含作业排队，不等于计费或CPU时间）；工作流墙钟按createdAt到completedAt计算并单列原预算脚本计时。测量同类事件、记录SHA/并发/环境；单次波动如实标注，不承诺稳定时延降幅。
- 数据与发布安全、权限、并发锁、进程/Shell/安装等选定高风险契约有保留的有效自动化保护，平台检查按真实边界选择。
- 保留测试均有明确执行归属，PR 精简集和完整/定时集没有意外遗漏；测试路由自检对应新的分层策略，不继续机械要求每 OS 全量。跨平台完整检查每日自动运行并支持手动指定当前ref验证；失败必须作为失败的Actions检查可见，由后续修改该区域的维护者/Runner处置，禁止以长期无人执行的手动入口代替。发布前要求待发布SHA具备完整检查成功记录，失败或缺失不能声明可发布；不在本轮新增自动发布系统。交付需实际触发一次完整工作流验证路由和执行。
- 先运行受影响检查，再按现有规范完成 npm run typecheck、npm test、npm run build、memsphere validate；明确当前验证与历史基线，不以历史通过代替。
- 存在 Memory 差异时执行最终 memory change validate 并记录 ChangeSet ID、状态和 View URL；不存在则不创建空 ChangeSet。
- 产品/研发/测试/架构 Agent 完成对应评审，Human 作为额外架构师确认方案与最终成果；不代替 Human 投票。最新 PR 全部适用检查成功后交 Human 合入。
