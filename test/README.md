# 测试层级

`*.unit.test.ts` 是本轮逐用例拆分后的单元入口。它们验证纯计算、解析、校验、内存状态或注入替身后的单个契约；可以读取静态 fixture，但不启动真实浏览器、服务或子进程，也不把产品的真实持久化读写归为单元测试。

其余 `*.test.ts` 保留集成与模块协作契约，暂时不在 CI 执行。文件较长或名称包含某个业务模块，都不能单独决定测试层级。

混合文件的单元用例移入同目录同名 `.unit.test.ts`；原集成文件保留共享前置构造和集成断言。纯单元文件只改入口名；拆分不会删掉原有集成测试，也不会把它们用 mock 改写为更弱的单元测试。

`npm run test:unit` 构建后执行全部单元文件；`node scripts/ci/run-tests.mjs --suite=unit --list` 只查看选取结果。`npm test` 仍保留本地全部测试入口，浏览器等环境依赖需按对应测试准备。当前 CI 的 unit-only 范围是临时探索安排，不代表集成行为已经通过验证。
