# TOS JSON ValueStore

Factory `memsphere/tos-json` stores model values directly as readable UTF-8 JSON at `prefix + id + ".json"`, using the official Volcengine SDK. ValueStore has one behavior and no `mode` field.

```json
{
  "region": "cn-beijing",
  "endpoint": "tos-cn-beijing.volces.com",
  "bucket": "lyj-test",
  "prefix": "values/",
  "credentials": { "source": "settings", "id": "my-tos" },
  "dataTimeoutMs": 120000,
  "controlTimeoutMs": 120000
}
```

Credentials also support the existing `source: "env"` AK/SK/optional STS variable references. Each Store binds one model. Factory creation accepts its Runtime, validates JSON support and the never-versioned bucket requirement. CLI `data store create --kind value --factory memsphere/tos-json --config-file ...` and View use this binding; timeout and credential references remain editable while identity, model and location stay fixed.

All standard methods are supported: get, has, create, update, atomic upsert, delete and paginated list. Update/delete accept optional expectedRevision. The public token is the raw single object ETag; wildcard and condition lists are invalid. Pass a token back unchanged. A write observes metadata through HEAD and submits at most one conditional PUT; a competing change fails directly, with no automatic retry. Create rejects a live ID, but may replace a tombstone. Delete is hidden by get/has/list and same-ID create is allowed. This differs from the DataStore's publicly readable deletion marker.

The envelope holds storageVersion, id, model, mutationId, is_delete and, when live, timestamps and value. An internal eight-byte cryptographic random mutation identity is encoded as sixteen lowercase hex characters; callers never supply it and it is not part of value. It changes the body for repeated business values, reducing historical ETag reuse; uniqueness is probabilistic, not an ordering or permanent ABA guarantee.

Metadata mirrors storageVersion (`memsphere-storage-version`), model, deletion (`memsphere-is_delete`, string true/false), timestamps and optional creator. Metadata and body are submitted in one PUT; HEAD avoids downloading the old value, and GET verifies their correspondence. ETag is generated by TOS and is not written into the body.

JSON encoding/decoding uses chunks, with strict JSON/Runtime validation and an input snapshot. Callers still receive a complete JavaScript value and need adequate memory; strings and other values remain subject to JavaScript representation limits. A defensive 4 GiB complete-object cap reports VALUE_TOO_LARGE. It is not a throughput or measured-capacity promise; capacity stress/boundary tests are not part of validation. No multipart upload, offline fallback, migration or history recovery is provided. Ordinary correctness uses small representative records.

Data/control timeout fields are optional positive integer milliseconds in 1..2147483647, both default 120000. GET/PUT use dataTimeoutMs (including logical deletion PUT); HEAD/list/versioning use controlTimeoutMs. Budgets cover the request and its response body, not an entire multi-request command. Parent cancellation can terminate earlier. Settings apply to subsequently opened Store clients, preserve current requests and do not invalidate pagination cursors. Unknown write outcomes are reported; reread before submitting a new write. Removing a binding preserves cloud objects.
