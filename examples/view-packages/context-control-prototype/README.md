# 上下文控制首版交互原型

本原型用于确认需求契约中的依赖图和产物/Review 双栏浮窗。正式界面是现有 Run 模块的另一种详情展示形态，复用其入口、列表、详情与浮窗；不新增前端模块或一级导航。当前代码只是临时预览 Package，使用真实 Shell 搭载固定示例，不连接模型 Store，也不写入真实 Run。

## 预览

使用支持 `router.register` 的当前 Memsphere CLI：

```bash
node examples/view-packages/context-control-prototype/preview.mjs --project memsphere --port 30025
```

预览服务使用已安装 CLI 的真实 View Shell，在当前进程中临时增加预览容器（正式实现归入既有 Run 模块）；不修改 Home 的安装配置，也不重启既有 View 服务。若 PATH 中不是目标版本，可通过 `--cli /absolute/path/to/dist/cli.js` 选择。

入口：`http://localhost:30025/projects/memsphere/modules/context-control-prototype`。

## 演示场景

| 场景 | 可检查的交互 |
| --- | --- |
| 运行中的探索 | 默认只有 A v2 → B v3 → C v2 三个节点，七份记录的历史版本收起 |
| 查看 B 最新版 | 点击「存储方案」，左侧正文和版本选择，右侧 评审参与者和评论 |
| 查看旧 B | 点击节点「历史版本」选 v1，仅将图切换为 A v1 → B v1 → C v1；点击具体产物才打开内容及评审浮窗 |
| 无 Review | 点击 C 或 C′，右侧显示暂无评审，不伪造通过结论 |
| 版本翻阅 | 图上的历史选择只切换图；浮窗内上一版/下一版或版本选择保持浮窗打开，直接更新正文和评审，背后同步切图 |
| 尚无下游 | B v2 只展示 A v2 → B v2，不错接其他版本的 C |
| 已交付探索 | 默认精确交付闭包；通过节点历史按钮翻阅，点击「回到交付视图」恢复，不把所有历史铺开 |
| 空运行 / 读取失败 | 独立空态与失败提示；失败场景可重试返回可读图 |
| 窄屏 | 浮窗切换「产物内容 / Review」，图允许横向滚动；关闭或 Escape 后返回原节点 |

首版正式实现需将本地示例替换为新模型 Store 的读取 API；原型不证明 CLI、存储、故障恢复和正式运行数据接口已经实现。图上编辑、拖拽编排、投票、正式轮次和生产写入不是本原型的交互目标。

## 关键界面约定

- 当前运行名称和状态统一放在顶部标题栏，内容区不重复展示。
- 图中只画真实 `dependencies`；`revisedFrom` 用于历史分组，修订不是自动依赖。
- 运行中默认展示最新版本；已交付时默认精确交付闭包，历史通过按钮翻阅，图跟随所选版本的上下游变化。
- 图上与浮窗内的产物标签统一使用 `ctx.ui.badge()` 公共组件；图上隐藏 default，浮窗显示完整标签。
- Artifact 选择以 ID 为准，旧版本和新版本的内容与 Review 严格对应。
- 浮窗区域与现有 Run 评审浮窗对齐：桌面约占视口宽高的 90%，760px 及以下铺满；桌面左内容、右评审，窄屏使用同一浮窗内的两项切换。
- 轻量 Review 展示具体意见，不引入自动通过/拒绝结论或投票控件。
- 页面仅保留「原型」标记；固定演示内容不代表真实执行结果。

## 入口加载约束

当前 View Host 直接提供 `module.json` 中的入口 JS，不负责把相对 import 的辅助文件映射成资源地址。本原型保持单个 `index.js` 入口，只有 `@memsphere/view-sdk` 由 Host 的 import map 提供。以后拆分源文件时，必须先构建为单个 ESM 入口，并检查浏览器实际请求到的全部模块；入口返回 HTTP 200 不足以证明其依赖可用。

界面文案与 Run、Artifact、Review 的模型名称、字段和状态一致；仅保留必要操作与空态/错误提示，不展示功能介绍和操作说明。
