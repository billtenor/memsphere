# 上下文控制首版原型与需求对照

关联 Run：`run-20261022-130223z-496d73ae`。

原型用于确认现有 Run 模块的另一种详情展示形态：以产物依赖图查看运行，并在浮窗中对照产物与评审。正式界面复用 Run 的入口、运行列表、详情和浮窗框架，不新增前端模块或一级导航。

当前预览代码暂以独立 Package 在真实 Shell 中搭载固定示例，以隔离演示数据；这是临时预览容器，不是正式前端模块划分，也不是新 CLI、Store 或接口已实现的证据。

## 页面布局约定

| 区域 | 展示及交互 | 首版边界 |
| --- | --- | --- |
| Run 模块 | 复用现有运行入口、列表、详情、Header、主题与浮窗框架；产物图是 Run 的另一种详情展示形态 | 前端按运行数据适配不同展示，后端仍区分新模型 Store 与旧流程持久化；不新增独立模块/一级导航 |
| 顶部标题栏 | 展示当前 Run.name 和 Run.status，随运行选择更新；原型标记也在标题栏内 | 内容区不重复展示名称和运行状态 |
| Run 列表 | 选择要查看的自由探索 Run | 原型列出四个演示场景；正式版本复用现有 Run 列表展示真实运行，不增加独立列表 |
| 依赖图 | 节点展示产物名称和标签，不展示 ID；ID 放在详情浮窗。实线表示 dependencies，方向为依据到下游 | 简单布局即可，不要求拖拽、图上编辑或图编排执行 |
| 历史版本 | 同一产物默认仅展示最新版本；节点的「历史版本」按钮展开可滚动版本列表 | 不把几十份修订并排铺成图；分组根据 revisedFrom，不按名称猜测 |
| 产物浮窗左栏 | 选中版本正文、ID、状态、标签、真实依赖及版本选择 | 提供上一版、下一版和版本列表；切换时保持同一个浮窗打开，直接更新内容与评审，背后的依赖图同步切换，内容只读 |
| 产物浮窗右栏 | 该具体 Artifact ID 的 评审参与者、时间和评论 | 轻量 Review 没有正式投票；不制造通过/拒绝状态 |
| 无 Review | 明确显示暂无评审 | 没有记录不能等价为通过，读取失败也不能当作暂无记录 |
| 浮窗尺寸 | 沿用现有 Run 评审浮窗的区域：桌面约占视口宽高的 90%，760px 及以下铺满视口 | 取消 1180×780 固定上限，圆角、阴影和遮罩跟随公共主题 |
| 浮窗退出 | 关闭按钮、Escape；返回原选择节点 | 焦点能回到节点，继续查看图 |
| 窄屏 | 图允许横向查看，浮窗内切换产物内容与 Review | 同一份信息换排布，不另建移动端业务流程 |

原型的参与者名称为固定演示数据，按 Review.reviewer.actorId 显示；不表示已经验证具体身份或正式授权。首版右栏只展示评论，不增加轻量结论、处置状态或正式审批语义。

## 界面文案

界面使用模型中的实体名称、字段语义与状态，不展示功能介绍、实现原理或操作教程。

| 界面文字 | 模型依据 |
| --- | --- |
| 运行、运行名称 | Run、Run.name |
| 运行中 / 已完成 / 已废弃 | Run.status：running / done / abandoned |
| 最终交付物 | Run.finalArtifactIds |
| 产物、产物名称 | Artifact、Artifact.name |
| 草稿 / 已提交 | Artifact.status：draft / submitted |
| 产物内容、依赖、标签 | Artifact.content、dependencies、tags |
| 评审、评审参与者、评论 | Review、reviewer、comments |
| 历史版本、上一版、下一版 | 根据 revisedFrom 计算的浏览操作，不是新增持久化字段 |

图上节点和产物浮窗中的标签统一使用现有 `ctx.ui.badge()` 公共组件，沿用组件的尺寸、胶囊圆角和主题颜色，不另写标签样式。图上继续隐藏 `default` 标签，浮窗显示完整标签。

页面不显示「来源声明」「交付闭包」「上下游同步变化」等说明文案。读取失败、暂无产物、暂无评审保留为必要状态提示；读取失败不作为 Run.status。

## 版本浏览规则

- 图是查看投影，底层 Artifact、dependencies 和 revisedFrom 不变。切换版本不执行回退命令，也不修改 Run 的交付选择。
- 运行中默认查看最新产物；已交付默认查看 finalArtifactIds 的精确依赖闭包，不能用较新版本替换交付时引用的旧 ID。
- 点击节点下的「历史版本」选择任一版本，只切换依赖图，不自动打开浮窗。在浮窗中用上一版、下一版或下拉列表切换时，保持浮窗打开，直接更新正文和评审，背后的依赖图同步切换。列表限定高度并可滚动，不随历史数量拉长主图。
- 选择某个历史版本后，图切换到它的实际上下文：追溯该 ID 的上游，再沿 dependencies 查找真正使用它的下游；不沿 revisedFrom 接下游，不按时间截断整张图。
- 下游包含多个兼容修订时默认收起历史；始终保留所选版本的实际依赖，不能用最新同名产物替换。没有下游就不展示下游。
- 只有点击具体产物才打开内容/评审浮窗，打开详情不重新选择或改变图的版本上下文。内容和 Review 均按该产物的具体 ID 查询；关闭浮窗后保持所选版本的图。点击「回到最新 / 回到交付视图」恢复默认查看。
- 版本号和收起状态为展示数据，不给 Artifact 增加持久化字段。本原型演示线性修订；正式实现遇到分支或一个产物明确依赖同一修订族的多个 ID 时，须保留真实引用，不能为了折叠而删边或造边，具体呈现由实施方案明确。

## 原型与正式交付的差异

| 项目 | 原型 | 正式交付必须满足 |
| --- | --- | --- |
| 数据来源 | Module 内固定示例 | 新领域服务读取 Run、Step、Artifact、External、Review 对应模型 Store |
| 列表与图 | 临时容器中的四个场景、七份记录，默认三个节点 | 正式界面归入现有 Run 模块，复用既有入口与列表； 历史默认收起；分组根据修订关系，排序由真实提交顺序确定；不能按名称或 Store 枚举顺序拼凑关系 |
| 更新 | 切换场景模拟状态 | CLI 生产后刷新可读取新数据；终态只读，历史可追溯 |
| 内容与意见 | 固定正文和评论 | 精确按 Artifact ID 查询；contentRef 通过 Store 读取 |
| 状态覆盖 | 演示图、空态、页面读取失败和无 Review | 还要区分单份内容/Review 的读取失败、无效引用及不支持预览的格式 |
| 验收证据 | Host 装载、源码检查及获准后进行的原型浏览器检查 | 真实数据与真实 Shell 的 CLI/浏览器联动、自动化回归及故障恢复证据 |

原型确认后，将上述布局和交互作为需求契约的首版基准。若后续实现需要改变范围或交互语义，先更新需求契约，再进入实施；不能以固定示例已经可点开来代替正式 Store 和接口验收。
