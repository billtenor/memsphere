# 当前迭代需求契约：上下文控制自由探索、轻量 Review 与首版界面

Run：run-20261022-130223z-496d73ae

版本：正文为第 4 版需求，已在 round-20261024-092331z-93d24a8d 通过。文末追加实施方案评审期间的需求补充，单列新范围及验收。Human 已在实施方案第4轮明确确认该固定补充并投通过票；不改写历史固定材料。新方案采用补充后的规则，冲突项在补充中逐项指出。

## 整体目标

让 Agent 通过 Memsphere CLI 自由展开上下文：在同一 Run 中持续提交 Artifact，声明产物依赖，通过轻量 Review 记录 Agent 或 Human 的修改意见，读取旧成果并修订、回到上游重新生产下游，最终选择交付产物。首版同时交付可查看 Artifact 依赖图和产物/Review 的最小前端，保证开始生产后可以直接查看上下文。操作动线及接口依据当前 Workspace 的 docs/context-control-exploration-cli.md 和本次对话已确认规则。

## 数据模型、模块与持久化边界

| 层面 | 本轮必须满足的要求 |
| --- | --- |
| 模型来源 | 以已经逐项确认的 memsphere/context_control/run.json、step.json、artifact.json、external.json、review.json 为新领域基准，沿用既定字段及含义，不能复制旧 RunState 另建同义状态 |
| 模型 Store | 新 Run、Step、Artifact、External、Review 全部通过各模型对应的 Store 读写；已有 dataStore/valueStore 抽象可以复用，禁止另写脱离模型的原生 JSON 状态文件作为权威数据源 |
| 首版后端 | 使用 JSON 文件 Store 实现；JSON 文件是 Store 的具体后端，不是新领域的持久化契约，优先复用现有 JSON ValueStore Factory |
| 可替换性 | 新领域服务只依赖模型及 Store 接口，不能扫描物理目录、拼接原生状态文件路径，后续可用远端 Store 替换 JSON 文件后端 |
| 独立领域模块 | 后端为上下文控制建设独立的领域与应用服务，负责新模型生命周期、依赖、标签及轻量 Review，不反向依赖旧流程的本地文件结构和单体 RunState。此边界指后端服务组织，不表示新增前端 View Module |
| 前端归属 | 产物依赖图是现有 Run 模块的另一种详情展示形态，复用既有运行入口、列表、详情和浮窗框架；在现有 Run 模块内按运行数据适配既有流程展示或产物图，不新建上下文控制前端模块、一级导航或独立运行列表。不同持久化来源由服务适配，不要求本轮统一存储 |
| CLI 路由 | 同一套 run 命令外观按自由探索/流程执行选择不同应用服务；启动自由探索使用新模块，新建或读取既有流程执行继续使用旧模块，不要求本轮统一存储 |
| 状态字段 | 新模块直接使用已确认的 memoryRef、frames、各 Config、Step.artifact、Artifact.status/tags 等新字段；不把旧命名包装后继续持久化 |
| 渐进迁移 | 设计清楚的领域服务/Store 边界，使将来旧执行器能逐步调用新能力；本轮不迁移旧运行，不实现全量双写、自动目录扫描迁移或重新设计新模型全部字段 |
| 必要模型差异 | 轻量 Review 的轮次可选、意见来源表示和读取记录承载方式，在实施方案中逐项列出最小变更后评审；读取记录在既定五个领域模型内承载。本轮不新增第六个领域模型或独立辅助 Store，不新增旧式 Assignment/Event 等整套实体；确需新增时先修订需求契约并重新确认 |

“自由探索不做业务 Model 校验”指产物不需要预配置业务内容标准，不代表领域数据绕过 Model Store：五个领域模型自身的结构与引用约束必须执行。

## 当前迭代范围

| 能力 | 交付要求 |
| --- | --- |
| 自由探索 Run | 不指定流程记忆时启动自由探索；可查看状态、上下文概览、按根产物展开依赖并恢复工作 |
| 普通产物提交 | 支持直接文本、正文文件与结构化入口；成功上报生成具体 Artifact ID，自动创建并关联最小 Step，无需开始工作信号 |
| 不可变成果 | 普通 report 只提交完整成果；不提供普通 draft 或通用 artifact submit；已提交内容、依赖和修订来源固定，标签可更新 |
| 依赖 | 支持 Artifact 和 External 的具体 ID，同一 Run 内引用，禁止自依赖和环；读过不等于依赖 |
| 外部资料 | 支持 source + content 字符串入口及结构化文件，查询已固定的材料和来源 |
| 轻量 Review | 无 Reviewer 配置和正式轮次即可对产物记录意见；参数使用 reviewer，支持 agent/human 来源；human/agent 表示声明的意见来源类别，Human 意见可由 Agent 代录；不将该参数展示为经过认证的具体个人身份或正式授权，也不授予正式代理投票权限 |
| 结构化输入边界 | --file 只接收提交输入，不接收完整 Artifact 记录。允许 name、content 或 contentRef、dependencies、tags、revisedFrom、revisedSummary；id、stepId、status 由系统生成，传入这些字段或未知字段一律拒绝，包含 status=draft。原文、文件正文、结构化内容三种入口互斥；content/contentRef 二选一；同一字段不能同时来自结构化文件和命令行参数。先验证输入再创建 Step 和 Artifact |
| 多条评论 | --comment 可重复，一次命令生成一份 Review、多条按顺序保存且各有 ID 的评论；也支持评论文件 |
| 修订与回退重走 | report --revised-from 创建新成果；自动保留修订关系，旧产物和意见可读；上游修改不改写旧下游，使用相同读取和上报命令重新生产，无独立 rewind 命令 |
| 依赖继承 | 修订未传依赖时继承旧产物的具体 ID；显式依赖完整替换；结构化文件 dependencies: [] 表达清空；revisedFrom 不隐式加入依赖 |
| 标签 | Artifact.tags，每份包含 default，作用域为所属 Run；report 可重复 --tag；已有产物可以打标签 |
| 标签依赖快捷选择 | --depends-on tag:<标签> 在本次提交前展开匹配的已提交产物并去重，排除本次新产物自身；最终仅保存 ID，后续打标签不自动加入；默认标签涵盖历史分支，不隐含只取最新版本 |
| 读取与候选提示 | 支持原文打印和 --out 写文件，均记读取行为；提供 Run 内近期读取候选摘要，不自动加依赖、不阻断 report、不增加确认参数；不监控外部编辑器读取 |
| 交付与取消 | 显式选择一份或多份提交产物完成 Run，以其依赖闭包展示交付结果；轻量 Review 不作门禁，其他分支保留历史；废弃仅按 Human 决定执行 |
| 首版前端 | 在现有 Run 前端模块的运行详情中提供 Artifact 依赖图展示形态，以本轮交互原型和对照说明为首版基准；点击节点打开浮窗，左侧展示该产物内容，右侧展示该产物的 Review 评论/意见；CLI 与 View 读取同一组模型 Store 数据，不复制旧 RunState 作为新界面数据源 |
| 一致交付 | 包含适用的 CLI 帮助、System Memory、Skill、模型与自动化测试更新，反映实际交付能力 |

## 首版前端要求

| 场景 | 用户操作 | 必须看到的结果 |
| --- | --- | --- |
| 开始查看探索 | 从现有 Run 模块的运行入口/列表打开自由探索 Run | 默认收起历史修订，展示最新产物及真实依赖连线；运行中可查看已生产结果，不要求先 finish |
| 查看产物 | 点击某个 Artifact 节点 | 打开浮窗，左侧显示该具体 ID 的内容及基本信息，右侧显示该 ID 对应的 Review 评论/意见 |
| 尚无 Review | 打开尚未被评论的 Artifact | 右侧明确显示“暂无评审”，不伪造通过或要求修改状态；轻量 Review 不强加正式投票语义 |
| 翻阅修订 | 点节点历史按钮，或在浮窗选择版本、上一版/下一版 | 图上的历史选择仅按所选具体 Artifact ID 切换依赖图，不自动打开浮窗；点击具体产物才查看其内容与 Review。浮窗内切换版本时保持同一个浮窗打开，直接更新正文、Review 及背后的上下游依赖图。无下游就不展示，不把其他版本的下游接过来，不按名称配对，也不修改任何持久化关系 |
| 继续生产后查看 | CLI 新增产物、依赖或轻量 Review 后刷新页面 | 图和浮窗可读取同一模型 Store 的最新数据，关闭浮窗可返回图继续选择 |
| 已交付或查看历史 | 查看完成的 Run，通过版本按钮翻阅，再回到交付视图 | 默认按 finalArtifactIds 的精确依赖闭包展示，不把历史全铺开；浏览版本不修改交付根或原始依赖；已完成运行保持只读 |
| 空数据与读取失败 | 打开空 Run，或请求的内容/Review 无法读取 | 有明确空态或失败提示，不把读取错误伪装成空内容或暂无意见 |

第一版聚焦只读查看：图可以使用简单布局，不要求拖拽编排、图上修改、复杂过滤、自动重放或新的正式评审交互。产物以本轮支持的文本/Markdown/JSON 等形式展示，contentRef 通过 Store 读取；不支持直接预览的内容明确给出类型和可访问方式。External 依赖在详情中保留引用，不误显示为丢失的 Artifact。

### 原型确认后的界面契约

| 区域或操作 | 确定规则 | 数据或组件依据 |
| --- | --- | --- |
| 前端位置 | 复用现有 Run 模块的入口、运行列表、详情与浮窗框架，产物图作为运行详情的另一种展示形态 | org.memsphere.run；现有 /projects/:projectId/tasks 与 /tasks/:runId 路由体系，不强加新的展示开关或领域字段 |

| 标签 | 图上与浮窗统一使用现有 badge 公共组件，尺寸、圆角和颜色跟随当前主题；图上隐藏 default，浮窗展示完整标签 | ctx.ui.badge()；Artifact.tags |
| 历史收起 | 默认只展示当前有效版本，不把同一产物几十次修订平铺成独立路径；历史按钮展开可滚动版本列表 | revisedFrom 只用于历史分组，不当作依赖边；不增加持久化版本号或 selection 字段 |
| 图上选历史 | 选择历史版本仅切换依赖图，不自动打开浮窗；点击某个具体产物才打开详情，打开详情不另行改变当前图的版本选择 | 选择具体 Artifact ID |
| 历史上下游 | 上游按所选 ID 的实际 dependencies 追溯；下游仅包含真正使用该版本的结果；没有下游就不展示，不把其他版本的成果接过来 | 固定的 dependencies，不自动换写旧引用；版本浏览不修改任何产物或 Run |
| 桌面浮窗 | 左侧显示所选产物的正文、ID、标签及依赖，右侧显示该具体 ID 对应的评审参与者、时间与评论 | Artifact.content 或 contentRef；Review.artifactId |
| 浮窗内翻页 | 上一版、下一版和版本选择均保持同一个浮窗打开，直接切换正文与评审；背后的依赖图同步变化，避免关闭、重开或回到背景抢焦点 | 按具体 Artifact ID 更新同一浮窗，首尾版本的对应按钮禁用 |
| 关闭与返回 | 关闭/Escape 后保持刚查看版本的图，焦点返回对应节点；可一键回到最新或交付视图 | 仅改变界面查看状态 |
| 浮窗区域 | 沿用现有 Run 评审浮窗的宽大区域，桌面约占视口宽高的 90%，取消 1180×780 的固定上限；760px 及以下铺满可用视口 | 公共主题的圆角、阴影、遮罩；窄屏保留内容/评审切换 |
| 文案 | 使用“运行、产物、评审、评论”等模型名称及实际状态，删除功能介绍、操作教程、实现原理与重复信息；空态、错误及必要按钮文字保留 | Run.status：运行中/已完成/已废弃；Artifact.status：草稿/已提交；读取失败不是 Run.status |
| 已完成运行 | 默认展示 finalArtifactIds 的精确依赖闭包；允许按版本查看历史并返回，不因浏览改变交付根，不用“最新”版本替换交付时固定的 ID | Run.finalArtifactIds |

原型中的 ID、示例名称、版本数和评论是演示数据，不是固定业务值；正式实现必须读取实际模型 Store。界面只保留一个原型标记；正式版本不保留此标记。轻量评审仅展示评论，不新增结论、投票或意见处置生命周期。

## 已调查的现状

- 当前 src/commands/run.ts 的启动入口要求流程名称或文件；report 围绕流程当前步骤处理，尚未提供上述自由探索语义。
- 当前运行状态和正式 Artifact Review 依赖既有流程执行器；项目中的上下文控制模型已经整理，但不等于执行器已迁移。
- 项目模型包已为 memsphere.context_control，五个模型位于 memsphere/context_control/；Artifact.tags 已补入项目模型，自动赋值和标签解析仍待实现。
- 轻量 Review 需要适配现有必填轮次和正式参与者约束；实施方案必须说明如何承载及兼容正式评审，不能用示例配置替代实际能力。
- Workspace 当前已有两份设计草案未纳入 Git：docs/context-control-exploration-cli.md、docs/procedure-graph-syntax.md。当前迭代按实际相关内容纳入交付，不擅自提交另一份图编排设计。

## 向前兼容

结论：不需要向前兼容。

本地 Git 未发现名称含 stable 的 Tag，当前不将未发布的项目模型草案和所有历史内部持久化形态纳入自动迁移责任。与此同时，「自由探索与既有流程并行可用」是本迭代产品要求，必须保留已存在的流程入口及其回归行为。实施方案应说明新增持久化格式的识别方式和不支持旧记录时的明确行为，不静默转换历史数据；若后续确认了相关 stable checkpoint，先更新本契约的兼容范围再实施。
