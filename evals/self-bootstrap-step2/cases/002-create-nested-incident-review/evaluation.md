# 评分指南

本文件只供父 agent 评分使用，其内容不得展示给子 agent，也不得复制到临时工作区。

## 期望行为

子 agent 应读取“故障复盘”Schema，并按照嵌套 `fields` 创建 `artifacts/incident-review.md`。“发生时间”和“恢复时间”应位于“基本信息”之下，“受影响服务”和“用户影响”应位于“影响”之下。

参考结构：

```markdown
# 故障复盘

## 基本信息

### 发生时间

2026-07-14 09:20

### 恢复时间

2026-07-14 10:05

## 影响

### 受影响服务

订单服务

### 用户影响

120 名用户无法提交订单。

## 根因

网关证书过期。

## 改进项

增加证书到期前 30 天的自动告警。
```

## 必须满足

- 子 agent 实际读取了当前工程中的“故障复盘”Schema。
- 创建了 `artifacts/incident-review.md`。
- “基本信息”和“影响”是 Markdown 标题。
- 两个时间字段的标题层级深于“基本信息”。
- 两个影响字段的标题层级深于“影响”。
- 根因和改进项以与“基本信息”“影响”同级的标题表达。
- 时间格式、影响人数、故障原因和改进措施与任务输入一致。
- 没有修改任何 Memory。

## 允许差异

- 顶层标题可以省略，或使用“故障复盘”“订单服务故障复盘”。
- 各层从几个 `#` 开始不作限制，只要求父子层级关系正确。
- 文字可以改写，但事实必须完整。

## 失败条件

- 没有创建目标文件，或保存到其他路径。
- 把嵌套字段全部写成同级标题。
- 使用项目符号、粗体标签或表格代替 Schema 要求的标题结构。
- 缺失任一字段，或改变时间、人数、根因或改进措施。
- 修改、删除或新增了任何 Memory 文件。

## 无效条件

- 子 agent 读取了本 `evaluation.md`。
- 子 agent 读取了当前工程以外的文件，或继承了此前讨论 memsphere 的上下文。

## 结论

- `pass`：满足全部必需条件，且没有失败或无效条件。
- `fail`：验收过程未受污染，但出现至少一个失败条件。
- `invalid`：出现任意无效条件。
