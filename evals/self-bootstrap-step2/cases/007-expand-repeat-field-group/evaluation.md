# 评分指南

本文件只供父 agent 评分使用，其内容不得展示给子 agent，也不得复制到临时工作区。

## 期望行为

子 agent 应读取“发布变更核验记录”Schema，根据任务中的两项变更把 `!repeat.body` 整体展开两次，并创建 `artifacts/release-change-verification.md`。

参考产物：

```markdown
# 发布变更核验记录

## 发布版本

v4.0.0

## 变更项 1

### 变更内容

批量退款

### 负责人

林川

## 核验项 1

### 核验方式

20 笔回归订单

### 核验结果

通过

## 变更项 2

### 变更内容

账单导出

### 负责人

周岚

## 核验项 2

### 核验方式

对比 5 份导出文件

### 核验结果

通过

## 发布结论

成功
```

## 必须满足

- 子 agent 实际读取了当前工程中的“发布变更核验记录”Schema。
- 创建了 `artifacts/release-change-verification.md`。
- “发布版本”和“发布结论”各使用一次 Markdown 标题，分别出现在全部重复字段组之前和之后。
- 产物包含两个“变更项”和两个“核验项”，顺序为第一项变更及核验、第二项变更及核验。
- 每个“变更项”下都有层级更深的“变更内容”和“负责人”标题。
- 每个“核验项”下都有层级更深的“核验方式”和“核验结果”标题。
- 第一组正确对应批量退款、林川、20 笔回归订单和“通过”。
- 第二组正确对应账单导出、周岚、对比 5 份导出文件和“通过”。
- 发布版本为 `v4.0.0`，发布结论为“成功”。
- 没有修改任何 Memory。

## 允许差异

- 顶层标题可以省略，或使用不改变文档含义的标题。
- “变更项”和“核验项”标题可以不带序号，也可以使用 `1`、`2` 或“第一项”“第二项”区分实例。
- 各层从几个 `#` 开始不作限制，只要求固定字段、重复字段和子字段之间的相对层级正确。
- 核验方式可以写成完整句子，文字可以调整，但事实和两组对应关系不能改变。
- 可以补充不改变发布事实的简短说明，但不能增加第三个重复字段组。

## 失败条件

- 没有创建目标文件，或保存到其他路径。
- 没有读取目标 Schema，仅根据任务文字自行发明结构。
- 只创建一个重复字段组、创建三个及以上字段组，或把两项变更合并到同一个“变更项”中。
- 分别集中列出两个“变更项”后再列出两个“核验项”，没有把 `body` 作为整组按轮次重复。
- “发布版本”或“发布结论”随 Repeat 重复，或出现在错误的相对位置。
- 把不同变更的负责人或核验信息串组。
- 使用表格、项目符号或键值列表代替 Schema 要求的标题结构。
- 缺少任一字段、事实错误，或核验结果不是“通过”。
- 修改、删除或新增了任何 Memory 文件。

## 无效条件

- 子 agent 读取了本 `evaluation.md`。
- 子 agent 读取了当前工程以外的文件，或继承了此前讨论 memsphere 的上下文。

## 结论

- `pass`：满足全部必需条件，且没有失败或无效条件。
- `fail`：验收过程未受污染，但出现至少一个失败条件。
- `invalid`：出现任意无效条件。
