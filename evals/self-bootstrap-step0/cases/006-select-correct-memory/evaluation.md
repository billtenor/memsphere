# 评分指南

本文件只供父 agent 评分使用，其内容不得展示给子 agent，也不得复制到临时工作区。

## 验收目标

当前工程同时提供“记账”和“报销申请”两份相关 Memory。任务使用“报销”这一别名，并描述一笔可记账、也可用于报销的业务支出。子 agent 应根据用户要“提交报销”的目标选择“报销申请”，而不是仅因存在支付行为选择“记账”。

## 期望产物

子 agent 应创建 `artifacts/reimbursement.md`，内容包含发生日期、费用内容、金额、业务用途和凭证编号，并符合“报销申请”Memory 的 outline 结构。

## 必须满足

- 子 agent 实际发现并读取了“报销申请”Memory。
- 创建了 `artifacts/reimbursement.md`，没有创建 `artifacts/bookkeeping.md`。
- 使用 Markdown 标题层级表达发生日期、费用内容、金额、业务用途和凭证编号。
- 日期为 `2025-07-18`，费用内容表达出租车费用，金额为 `120`，业务用途表达拜访客户，凭证编号为 `TAXI-0718`。
- 没有修改任何 Memory。

## 允许差异

- 子 agent 可以同时读取“记账”Memory 进行比较，只要最终选择正确。
- “出租车费用”“客户拜访交通费”等内容表达均可接受。
- 金额可以写成 `120`、`120.00` 或带“元”的等价形式。

## 失败条件

- 创建了记账记录，或同时创建记账记录和报销申请。
- 没有创建报销申请，或保存路径错误。
- 使用项目符号列表或表格代替报销申请 Schema 的 outline 标题结构。
- 缺失任一字段，或错误改变业务用途、金额、日期或凭证编号。
- 修改、删除或新增了任何 Memory 文件。

## 无效条件

- 子 agent 读取了本 `evaluation.md`。
- 子 agent 读取了当前工程以外的文件，或继承了此前讨论 memsphere 的上下文。

## 结论

- `pass`：满足全部必需条件，且没有失败或无效条件。
- `fail`：验收过程未受污染，但出现至少一个失败条件。
- `invalid`：出现任意无效条件。
