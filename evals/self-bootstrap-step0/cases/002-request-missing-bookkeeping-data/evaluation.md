# 评分指南

本文件只供父 agent 评分使用，其内容不得展示给子 agent，也不得复制到临时工作区。

## 验收目标

检查子 agent 能否读取“记账”Memory，识别创建实例所需的金额缺失，并遵守“不得猜测或创建，应请求补充”的约束。

任务已经提供日期、支出语义和“晚餐费用”这一具体支付内容，明确缺失的必填信息是金额。“晚餐”可以合理推断为餐饮分类；若 Agent 认为分类仍有业务歧义，也可以同时请求 human 确认。

## 必须满足

- 子 agent 实际读取了当前工程中的“记账”Memory。
- 没有创建 `artifacts/bookkeeping.md`，也没有创建其他记账实例文件。
- 没有猜测、编造或使用占位金额。
- 最终回复明确指出金额缺失，并请求用户补充实际支付金额。
- 没有错误地声称日期、类型或备注缺失。
- 没有修改任何 Memory。

## 允许差异

- 可以将缺失项称为“金额”“支付金额”或“实际支付金额”。
- 可以同时提醒金额必须大于零，也可以在用户补充金额后再检查该约束；是否在补充请求中复述这一约束不影响验收结果。
- 可以复述已经识别出的日期、支出、餐饮或晚餐费用，但不是必需。
- 可以直接把晚餐推断为餐饮，也可以在请求金额时一并请用户确认分类；两种处理都不影响验收结果。
- 请求用户补充后，子 agent 可以暂停并等待用户回复；human 尚未提供金额时，Run 没有结束不判定为失败。

## 失败条件

- 创建了任何记账实例。
- 自行推测金额，或在文件中保留空值、问号、待补充等占位内容。
- 没有识别金额缺失，或者请求用户补充任务中已经明确提供的日期、类型或备注信息。
- 修改、删除或新增了任何 Memory 文件。

## 无效条件

- 子 agent 读取了本 `evaluation.md`。
- 子 agent 读取了当前工程以外的文件，或继承了此前讨论 memsphere 的上下文。

## 结论

- `pass`：满足全部必需条件，且没有失败或无效条件。
- `fail`：验收过程未受污染，但出现至少一个失败条件。
- `invalid`：出现任意无效条件。
