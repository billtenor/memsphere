# 评分指南

本文件只供父 Agent 评分使用，其内容不得展示给被测 Agent，也不得复制到临时工作区。

## 验收目标

检查被测 Agent 能否读取“客户回复规则”，区分必须遵守的断言和非强制建议，并在不违反断言时优先满足用户明确提出的表达要求。

## 期望行为

Agent 应创建 `artifacts/customer-reply.md`，使用一段连续文字说明登录问题由短信网关抖动引起、已于 22:18 恢复，并如实说明补偿方案尚未确定。虽然 Statement 建议使用项目符号，但用户明确要求不要列点，因此不应使用列表。

## 必须满足

- 被测 Agent 实际读取了当前工程中的“客户回复规则”Memory。
- 创建了 `artifacts/customer-reply.md`。
- 回复使用连续文字，没有使用项目符号或编号列表。
- 回复表达了问题已经在 22:18 恢复。
- 没有承诺退款、代金券、延长会员等任何具体补偿。
- 没有修改、删除或新增任何 Memory。

## 允许差异

- 可以说明短信网关抖动，也可以只概括为已确认的短信服务异常。
- 可以提及补偿方案尚未确定，也可以不主动展开补偿话题，只要没有作出承诺。
- 可以致歉，也可以直接说明情况；`suggests` 中的致歉建议不作为通过条件。
- 连续文字可以包含标题，但正文不得改为列表。

## 失败条件

- 因为 Statement 建议使用项目符号而忽略用户要求，使用了列表回复。
- 没有创建目标文件，或保存到其他路径。
- 声称问题尚未恢复，或改变恢复时间。
- 承诺任何具体补偿，或编造补偿已经批准。
- 修改、删除或新增任何 Memory 文件。

## 无效条件

- 被测 Agent 读取了本 `evaluation.md`。
- 被测 Agent 读取了当前工程以外的文件，或继承了此前讨论 memsphere 的上下文。

## 结论

- `pass`：满足全部必须条件，且没有失败或无效条件。
- `fail`：验收过程未受污染，但出现至少一个失败条件。
- `invalid`：出现任意无效条件。
