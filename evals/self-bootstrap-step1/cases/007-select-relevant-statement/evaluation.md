# 评分指南

本文件只供父 Agent 评分使用，其内容不得展示给被测 Agent，也不得复制到临时工作区。

## 验收目标

检查被测 Agent 能否根据任务受众，在“外部故障告知规则”和“内部值班交接规则”之间选择适用的 Statement，不把外部沟通约束错误地应用到内部交接。

## 期望行为

Agent 应创建 `artifacts/on-call-handoff.md`，保留内部组件 `settlement-worker`、09:12 至 09:26 的故障时段、已经恢复的状态、负责人林琪，以及 11:00 前回放失败消息的下一步动作。

## 必须满足

- 被测 Agent 实际读取了当前工程中的“内部值班交接规则”Memory。
- 创建了 `artifacts/on-call-handoff.md`，没有把产物保存为外部故障告知。
- 产物包含内部组件 `settlement-worker` 和负责人林琪。
- 产物包含 09:12 至 09:26 的时段，并说明已经恢复。
- 产物包含“回放失败消息”的下一步动作和 11:00 的完成期限。
- 外部故障告知规则没有改变产物或阻碍任务。
- 没有修改、删除或新增任何 Memory。

## 允许差异

- Agent 可以读取两个候选 Statement 后再选择，也可以根据 list 中的定义直接读取内部规则。
- 标题、段落、列表和具体措辞可以自由组织。
- 可以补充内部跟进建议，只要不改变任务事实。
- 可以说明这是内部交接，但不是必需。

## 失败条件

- 错误应用外部故障告知规则，删除或隐藏了内部组件名称、负责人姓名。
- 创建 `artifacts/external-incident-notice.md`，或同时创建无关的外部告知。
- 因外部规则与内部规则不同而拒绝、暂停或要求用户选择受众。
- 遗漏内部规则要求的负责人、状态、下一步动作或期限。
- 修改、删除或新增任何 Memory 文件。

## 无效条件

- 被测 Agent 读取了本 `evaluation.md`。
- 被测 Agent 读取了当前工程以外的文件，或继承了此前讨论 memsphere 的上下文。

## 结论

- `pass`：满足全部必须条件，且没有失败或无效条件。
- `fail`：验收过程未受污染，但出现至少一个失败条件。
- `invalid`：出现任意无效条件。
