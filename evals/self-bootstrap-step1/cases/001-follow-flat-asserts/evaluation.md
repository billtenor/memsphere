# 评分指南

本文件只供父 Agent 评分使用，其内容不得展示给被测 Agent，也不得复制到临时工作区。

## 验收目标

检查被测 Agent 能否发现并读取顶层的“客户故障告知规则”Statement，完整应用一组平铺 `asserts`，并创建面向客户的故障告知。

## 期望行为

Agent 应创建 `artifacts/customer-incident-notice.md`，准确说明支付请求在 10:20 至 10:37 期间受到影响、约 8% 的请求失败且服务已经恢复。内容不得出现内部代号 `Atlas`，也不得编造题目没有确认的深层根因。

## 必须满足

- 被测 Agent 实际读取了当前工程中的“客户故障告知规则”Memory。
- 创建了 `artifacts/customer-incident-notice.md`。
- 产物表达了故障开始时间 10:20、恢复时间 10:37 和约 8% 的量化影响。
- 产物说明受影响的是支付请求，并且故障已经恢复。
- 产物没有出现 `Atlas`。
- 没有修改、删除或新增任何 Memory。

## 允许差异

- 标题、段落结构、语气和具体措辞可以自由组织。
- 可以写出日期，也可以只写时间；不得改变题目提供的时间事实。
- 可以把原因概括为“内部技术问题”或直接不写原因。
- 可以补充致歉、后续观察等不改变事实的内容。

## 失败条件

- 没有创建目标文件，或保存到其他路径。
- 缺少开始时间、恢复时间或量化影响中的任意一项。
- 暴露内部服务代号 `Atlas`。
- 编造数据库故障、配置错误、人为操作等未确认根因。
- 改变任务提供的故障时间、影响比例或恢复状态。
- 修改、删除或新增任何 Memory 文件。

## 无效条件

- 被测 Agent 读取了本 `evaluation.md`。
- 被测 Agent 读取了当前工程以外的文件，或继承了此前讨论 memsphere 的上下文。

## 结论

- `pass`：满足全部必须条件，且没有失败或无效条件。
- `fail`：验收过程未受污染，但出现至少一个失败条件。
- `invalid`：出现任意无效条件。
